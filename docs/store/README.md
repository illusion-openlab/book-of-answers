# 商店上架素材

PICO Developer Console 提交用的素材，尺寸与格式均按控制台的要求生成，已实测通过上传。

| 文件 | 用途 | 控制台要求 |
| --- | --- | --- |
| `icon-1024.jpg` | 应用图标 | JPG/JPEG，≤4 MB，1024×1024 |
| `icon_bg.png` | 分层图标 · 最底层 | PNG，≤4 MB，1024×1024 |
| `icon_fg2.png` | 分层图标 · 第二层 | PNG，≤4 MB，1024×1024 |
| `poster-wide-2560x1440.jpg` | 宣传海报 · 宽幅 | JPG/JPEG，≤5 MB，2560×1440 |
| `poster-square-1024.jpg` | 宣传海报 · 方形 | JPG/JPEG，≤5 MB，1024×1024 |
| `detail-01.jpg` … `detail-04.jpg` | 详情页图片 | JPG/JPEG/PNG，≤5 MB，2560×1440，4–7 张 |
| `promo-source.jpg` | 上面两张海报的源图 | 1672×941 |

## 几处需要知道的取舍

**应用图标是满幅方形，不是圆形构图。** 控制台只接受 JPG，而 JPG 没有 alpha 通道，
所以不能直接用 APK 里那张圆形（圆外透明）的 `ic_spatial_launcher.png` —— 透明区会变成实色。
这张改为星盘底图铺满整个方形 + 书，书的相对大小与圆形版一致，视觉上与 APK 内图标同源。

**分层图标直接复用 APK 里的两张。** `icon_bg.png` / `icon_fg2.png` 就是
`app/src/main/res/drawable/icon_3d_layer_0.png` / `icon_3d_layer_1.png` 的副本，
生成方式见 [`art/README.md`](../../art/README.md)。改图标时先跑 `art/build-icons.py`，再同步这两张。

**宽幅海报是放大的，源图不够大。** 源图 1672×941，控制台要求 2560×1440，放大约 1.53 倍
（先裁到精确 16:9 再 Lanczos 重采样，避免拉伸变形）。画面会略软。**若日后拿到更高分辨率的
原图，应当重做这张。**

**方形海报以书为中心裁切。** 源图是宽幅构图，裁成正方形必然要切掉一侧。取 x∈[689,1630]，
让右下角「点击翻开答案」按钮完整保留、书本落在 45% 处；代价是左侧「向内探索」卡片被切掉一部分。
另一种裁法会把 CTA 文字切在字中间，看起来像出错，所以选了现在这种。

**详情页图片是模拟器实拍。** 四张：第 1 张书合着、显示提示语，第 2–4 张分别是三个不同答案
（`关注生活本身` / `温柔的坚持就是胜利` / `明日曙光将四起`）。抓图时临时装了一个循环开合的探针，
抓完已撤除。

模拟器输出是 2160×2158 的近方形，需要裁成 16:9。**裁切带是按内容位置定的，不是按画面中心**：
面板与书本在原图里占 y∈[972,1366]，中心 y≈1169，因此取全宽、y∈[562,1777]（高 1215），
再重采样到 2560×1440（放大 1.19 倍）。按画面中心裁会把书切掉。

## 重新生成详情页图片

模拟器抓图无法脚本化复现（需要临时探针驱动开合、且答案是随机抽的），所以这四张是一次性产物。
若要重做：在 `HomeVolume` 里临时加一个循环 `bookState?.onTap()` 的探针、抓 4 张原图，
再按上面的裁切参数处理。
